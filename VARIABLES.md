# Variable reference

Inputs are per stack. Every stack's README lists its inputs and outputs
(generated by terraform-docs from the typed, described variables), and
[examples/](examples/) shows them in use.

## Common inputs (`environments/<env>/common.tfvars`, every stack)

Declared identically in every stack's `variables.common.tf`.

| Input | Type | Default | Description |
|---|---|---|---|
| `workload` | string | — | 2–8 lowercase letters/digits; part of every name |
| `environment` | string | — | 2–10 lowercase letters/digits (`dev`, `test`, `prod`, …) |
| `location` | string | — | primary region |
| `subscription_id` | string | — | workload subscription (GUID) |
| `naming` | object | `{}` | `unique_seed` (5 chars; derived when null), `name_overrides` (logical role → name, see [modules/naming](modules/naming/README.md)) |
| `tags` | map(string) | `{}` | merged with `workload`, `environment`, `stack`, `managed-by` |
| `enable_telemetry` | bool | `true` | AVM telemetry |
| `network_mode` | string | `greenfield` | `greenfield` · `alz_spoke` · `byo` ([DEPLOYMENT_GUIDE §5](DEPLOYMENT_GUIDE.md#5-network-modes)) |

## Where the old root inputs went

| Old root input | Now |
|---|---|
| `environment_name`, `resource_group_name`, `*_name` overrides | `workload` + `environment` (+ `naming.name_overrides`); resource groups come from bootstrap |
| `network.*` | `network.tfvars` (greenfield / alz_spoke) or `platform.tfvars` `network` (alz_spoke / byo) |
| `apim`, `usage_pipeline`, `monitoring` | `platform.tfvars` (same shapes; `usage_pipeline.ase` keeps `app_service_environment_id` and `zone_redundant`) |
| `ai_foundry_instances`, `ai_foundry_models`, `ai_foundry_external_access`, `foundry_*` | `platform.tfvars` `foundry` |
| `key_vault_sku`, `soft_delete_retention_days`, `purge_protection_enabled`, `kv_*`, `network_acl_default_action` | `platform.tfvars` `key_vault`; `kv_deployer_ip_rules` / `package_upload_ip_rules` → `dev_access.allowed_cidrs` |
| `redis_*`, `api_center_sku`, `apic_location`, `apim_log_*` | `platform.tfvars` `redis`, `api_center`, `apim_logging` |
| `features.semantic_cache`, `features.api_center` | `platform.tfvars` `features` |
| `features.pii_*`, `content_safety`, `azure_ai_search`, `document_intelligence`, `embeddings_backend`, `mcp_sample`, `api_center_onboarding` | `gateway-config.tfvars` `features` |
| `features.unified_ai_api`, `ai_model_inference`, `openai_realtime` | `llm-backend-onboarding.tfvars` `features` |
| `entra_auth_enabled`, `entra_*`, `enable_jwt_auth`, `jwt_*`, `enable_entra_id_setup` | `identity.tfvars` (the app) + `gateway-config.tfvars` `entra_auth` |
| `llm_backend_config`, `extra_llm_backends`, `configure_circuit_breaker`, `inference_api_type` | `llm-backend-onboarding.tfvars` |
| `enable_foundry_apim_connection`, `foundry_apim_connections` | an access contract with `foundry = { enabled = true }` |
| `rollout_phase`, `skip_logic_app_code_deploy` | gone: each stack is its own phase; `task logic-app-code` republishes the workflows |
| `create_apim_gateway_key_secret`, `kv_auto_detect_deployer_ip` | gone |
